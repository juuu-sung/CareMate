# User Scenarios

CareMate MVP에서 우선 구현하고 검증할 대표 사용자 시나리오 5개를 정리한 문서입니다.

이 문서는 다음 작업의 기준으로 사용합니다.

- 음성 대화 플로우 설계
- `/chat/speech` API 정의
- STT/LLM 프롬프트 설계
- 재확인 질문 로직 설계
- 테스트 발화셋 작성

## 1. 시나리오 선정 기준

대표 시나리오는 아래 기준으로 선정합니다.

- 고령 사용자가 실제로 자주 사용할 가능성이 높은가
- 노인특화 AI 에이전트의 핵심 역할과 직접 연결되는가
- 상용 STT, GPT/Gemini, 사투리 대응, 재확인 로직을 함께 검증할 수 있는가
- 보호자 기능 및 돌봄 모드와 연결될 수 있는가

## 2. 시나리오 1. 음성으로 오늘 일정 확인

### 목적

사용자가 음성으로 오늘 일정이 있는지 묻고, AI 에이전트가 실제 일정 데이터를 조회해 짧고 명확하게 답한다.

### 사용자 예시 발화

- "오늘 병원 가는 날이가?"
- "오늘 어디 가는 일정 있나?"
- "오늘 약속 있나?"

### 정상 흐름

1. 사용자가 말하기 버튼을 누른다.
2. 음성을 녹음하고 서버로 전송한다.
3. STT가 발화를 텍스트로 변환한다.
4. 에이전트가 일정 확인 의도로 분류한다.
5. 백엔드가 일정 데이터를 조회한다.
6. AI 에이전트가 짧고 쉬운 문장으로 응답한다.

### 기대 응답

- "오늘 오후 3시에 병원 일정이 있어요."
- "오늘 일정은 없어요."

### 재확인 필요 조건

- STT 결과가 불명확한 경우
- 오늘 일정인지 내일 일정인지 구분되지 않는 경우
- 일정 조회에 필요한 날짜 정보가 빠진 경우

### 구현 포인트

- STT -> 의도 분류 -> 일정 조회 -> 응답 생성 흐름이 안정적으로 이어져야 한다.
- 일정이 여러 개인 경우 한 번에 길게 말하지 않고, 가장 가까운 일정부터 우선 안내해야 한다.

## 3. 시나리오 2. 음성으로 복약 시간 확인

### 목적

사용자가 약 복용 시간을 물어보면 AI 에이전트가 실제 복약 데이터 기준으로 응답한다.

### 사용자 예시 발화

- "약 언제 먹으면 되노?"
- "오늘 약 먹을 시간 지났나?"
- "저녁 약은 몇 시고?"

### 정상 흐름

1. 사용자가 음성으로 질문한다.
2. STT가 발화를 전사한다.
3. 에이전트가 복약 확인 의도로 분류한다.
4. 백엔드가 복약 데이터를 조회한다.
5. AI 에이전트가 현재 시점 기준으로 필요한 정보를 짧게 알려준다.

### 기대 응답

- "다음 약은 저녁 8시에 드시면 돼요."
- "오늘 아침 약은 이미 확인되었어요."

### 재확인 필요 조건

- 어떤 약을 묻는지 불명확한 경우
- 오늘 약인지 특정 약인지 구분되지 않는 경우
- STT에서 시간 정보가 깨진 경우

### 구현 포인트

- 복약 질문은 일정 질문과 의도 혼동이 자주 날 수 있으므로 재확인 기준이 중요하다.
- 건강 관리 모드에서는 복약 관련 응답 우선순위를 더 높인다.

## 4. 시나리오 3. 말동무 대화와 정서적 응답

### 목적

사용자가 외로움이나 심심함을 표현했을 때 AI 에이전트가 짧고 부담 없는 정서적 반응을 제공한다.

### 사용자 예시 발화

- "오늘 좀 심심하네."
- "혼자 있으니 적적하다."
- "누가 말 좀 걸어주면 좋겠다."

### 정상 흐름

1. 사용자가 음성 또는 텍스트로 감정 표현을 한다.
2. STT 또는 텍스트 입력이 처리된다.
3. 에이전트가 말동무 대화 의도로 분류한다.
4. AI 에이전트가 공감 표현과 짧은 후속 문장을 제공한다.

### 기대 응답

- "심심하실 수 있어요. 오늘은 어떻게 보내셨어요?"
- "적적하셨군요. 잠깐 같이 이야기해볼까요?"

### 재확인 필요 조건

- 감정 표현인지 요청형 질문인지 구분되지 않는 경우
- 발화가 너무 짧거나 STT 오류가 심한 경우

### 구현 포인트

- 말동무 응답은 길지 않아야 한다.
- 과도한 조언, 진단형 표현, 부자연스러운 위로 문장을 피해야 한다.

## 5. 시나리오 4. 사투리나 애매한 표현으로 인한 재확인 질문

### 목적

사투리, 축약 표현, STT 오인식이 있는 상황에서 에이전트가 무리하게 답하지 않고 다시 확인한다.

### 사용자 예시 발화

- "내일 약 있나?"
- "병원 가는 기가 오늘이제?"
- "그거 그때 하는 거 맞제?"

### 정상 흐름

1. 사용자가 음성으로 질문한다.
2. STT가 전사하지만 일부 표현이 애매하게 인식된다.
3. 에이전트가 의도 분류 불확실 상태로 판단한다.
4. 에이전트가 재확인 질문을 먼저 한다.
5. 사용자가 다시 답하면 그때 실제 조회 또는 응답 생성으로 넘어간다.

### 기대 응답

- "내일 드시는 약 시간을 물으신 걸까요?"
- "오늘 병원 일정이 맞는지 확인해드릴까요?"
- "다시 한 번 천천히 말씀해 주세요."

### 재확인 필요 조건

- STT confidence가 낮은 경우
- 사투리 표현이 사전 또는 룰에 없는 경우
- 일정과 복약 중 무엇을 의미하는지 모호한 경우

### 구현 포인트

- 이 시나리오는 노인특화 AI 에이전트 품질의 핵심이다.
- 잘못된 확답보다 재질문이 우선되어야 한다.

## 6. 시나리오 5. 돌봄 모드에 따라 응답 방식이 달라짐

### 목적

같은 질문이라도 돌봄 모드에 따라 문장 길이, 설명 수준, 안내 방식이 달라지도록 한다.

### 사용자 예시 발화

- "오늘 일정 뭐 있노?"
- "약 언제 먹는지 알려줘."

### 정상 흐름

1. 사용자가 질문한다.
2. 에이전트가 현재 사용자 모드를 확인한다.
3. 같은 데이터 조회 결과라도 모드에 따라 응답 스타일을 바꾼다.

### 기대 응답

Basic Mode:
"오늘 오후 3시에 병원 일정이 있어요."

Cognitive Support Mode:
"오늘 3시에 병원 가요. 아직 시간 있어요."

Health Support Mode:
"오늘 오후 3시에 병원 일정이 있어요. 약 복용 일정도 함께 확인해드릴까요?"

### 재확인 필요 조건

- 현재 모드 정보를 불러오지 못한 경우
- 모드에 따라 추가 확인이 필요한 경우

### 구현 포인트

- 모드 차이는 기능 차이뿐 아니라 응답 스타일 차이로도 보여야 한다.
- 인지 지원 모드는 문장 길이와 정보량을 더 엄격하게 제한해야 한다.

## 7. 이번 단계에서 바로 연결할 구현 항목

위 5개 시나리오를 기준으로 아래 작업을 바로 진행합니다.

- `/chat/speech` 요청/응답 스키마 정의
- STT provider와 LLM provider 인터페이스 정의
- 재확인 질문 발생 조건 구체화
- 테스트 발화셋 초안 작성
- 모드별 응답 프롬프트 초안 작성

## 8. 후속 확정 항목

이 문서 다음 단계에서 추가로 확정할 항목은 아래와 같습니다.

- 음성 업로드 포맷과 길이 제한
- STT confidence 임계값
- 전사문 사용자 노출 정책
- 사투리 표현 1차 사전
- 실패 응답 문구 표준안
